## 1. 产品总览与定位
Onto 系列是**国产可执行本体（活本体）一体化平台**，核心主张：本体不再只是静态描述概念、存储三元组的知识库，而是可以承载业务规则、行为动作、因果推演、沙盘仿真、业务执行的“世界模型”。

核心Slogan：**从静态知识图谱，升级为可执行、可推演的活本体**。

定位对标：Palantir Foundry 轻量化国产替代方案，面向政务、安全、供应链、能源、制造等高确定性决策场景；区别于问答型GraphRAG、传统OWL本体编辑器。

设计哲学：**对象优先建模**。优先从业务对象、对象属性、行为、约束规则出发建模，再映射到底层数据表，对齐业务人员思维，降低业务与技术沟通鸿沟。

## 2. 完整产品体系（四大组件，闭环体系）
### 2.1 OntoGraph｜原生本体数据库（底座存储层，前身 AbutionGraph）
Onto体系的数据底座，是整个产品最底层的存储与基础推理引擎。
- 核心能力
    1. 同时支持 **RDF本体模式（OWL 2 DL / SWRL / SPARQL）+ 属性图** 双范式，兼顾本体标准规范与图开发习惯；
    2. 原生一等公民扩展：在传统TBox（概念）、ABox（实例）之外，原生内置 **Function（函数）、Action（行动）** 层；
    3. 内置时序、空间、向量、图谱一体化GHOLAP图数仓能力，支持时序演化、事实版本回溯、快照；
    4. 内置细粒度权限、数据视野隔离、敏感数据脱敏能力；
    5. 支持流式数据接入、增量本体推理，不是离线静态推理。
- 作用：存本体定义、实例数据、规则、动作定义、历史快照；向上给OntoFlow、OntoOS提供语义查询、推理基础。

### 2.2 OntoFlow｜本体智能应用开发平台（中层建模工作台，核心开发层）
面向业务+技术人员的本体工程化流水线平台，也是对外主推核心产品。
- 标准化四步流水线：**数据选择 → 数据处理 → 本体建模 → 查询设计**
- 核心能力
    1. AI辅助本体工程：自动探查数据源、抽取实体、识别关系、生成本体初稿；
    2. 对象优先可视化建模画布，支持多人协同建模、本体版本管理、变更对比；
    3. 本体校验、规则校验、推理一致性检查；
    4. 低代码查询设计：支持SPARQL、自然语言转语义查询，配置查询视图、报表；
    5. 输出成果：本体模型、查询资产、业务规则，直接交付给OntoOS用于推演执行。
> 核心理念：**本体构建完成，即是可运行系统**，不需要额外大量开发数据表、后端接口。

### 2.3 OntoOS｜本体推演决策平台（上层执行推演层）
活本体的执行引擎，是整套体系和传统本体工具最大差异的载体。
- 核心能力
    1. 因果推演、沙盘仿真、多副本隔离推演：创建独立沙盘副本做“假设推演”，推演过程不污染原始生产数据；
    2. Action/Function调度执行：本体上绑定的业务动作可以被触发，联动外部业务系统；
    3. HITL人在回路机制：AI推演生成方案、动作建议；高风险动作自动拦截，生成确认卡片，必须人工审批后才可以执行；全程可审计；
    4. 混合推理框架：OWL描述逻辑规则 + SWRL规则 + LLM语义辅助推理，兼顾确定性和开放性；
    5. 推演链路追踪、因果溯源：可以解释每一条结论、动作的推导来源。

### 2.4 OntoX｜本体孪生可视化平台（展示层配套）
配套可视化大屏、业务孪生组件。
- 能力：本体实例态势展示、推演过程可视化、传导链路可视化、业务看板；
- 定位：面向指挥、态势研判场景的上层展示载体，非核心建模和推理引擎。

> 体系闭环关系：OntoGraph（存）← OntoFlow（建）→ OntoOS（推、执行）→ OntoX（看）

## 4. 核心优势特点（对外宣传口径，适合汇报）
1. **本体工程流水线化，降低落地门槛**
   把本体建模从专家手工工作，变成标准化可迭代流水线；业务人员可以参与建模，不重度依赖本体专家、后端开发。
2. **标准兼容，不锁死**
   原生兼容OWL2 DL、SWRL、SPARQL国际本体标准；模型可以导出标准格式，具备迁移能力；同时兼容属性图开发习惯，兼顾两类开发者。
3. **轻量化国产方案，对标重型海外平台**
   对比Palantir Foundry：能力方向对齐，但架构精简、部署成本更低、国产化适配、自主可控，适配国内国企、政务、工业场景。
4. **确定性优先，适合高风险决策**
   和纯LLM、GraphRAG区别：以本体规则逻辑作为主推理底座，大模型仅做辅助；结论可溯源、可审计，适合不能幻觉的风控、应急、供应链研判场景。
5. **推演和生产隔离，沙盘安全试算**
   支持独立沙盘副本做假设推演（“如果发生XX，会影响哪些对象”），推演不会改动真实业务数据。
6. **人在回路安全闭环**
   自动化推演+人工审批结合，机器负责计算传导路径、生成方案，人掌握高风险动作最终控制权。

## 5. 差异化技术要点（核心，和同类产品不一样的地方）
> 这部分是最关键，区分它和 Protégé、GraphDB、Virtuoso、普通知识图谱、GraphRAG 的差异

### 5.1 数据模型层面：扩展本体范式，原生引入 Action / Function
传统OWL本体只有TBox（类、属性）、ABox（实例三元组），**只能描述“是什么”**。
OntoGraph 将 Function、Action 作为本体一等公民，本体模型里直接定义：对象可以做什么动作、动作入参、触发条件、后置影响。
👉 本质：本体从**描述型模型**升级为**可执行模型**。
> 传统方案做法：本体和业务动作分开两套系统，本体只负责查询，动作写在外部代码/规则引擎里，两者割裂，难以统一推演、溯源。

### 5.2 建模范式：对象优先建模，而不是表优先、三元组优先
常规图谱项目：先有数据库表，再逆向抽取三元组、构建本体；本体是数据表的附属映射。
OntoFlow：业务对象、行为、规则优先，本体是业务的第一模型，数据表是本体的存储映射产物。
👉 优势：业务语义稳定，底层存储可以随本体适配，业务变化优先修改本体，而不是改库表。

### 5.3 推理架构：混合推理 + 沙盘副本隔离推演
- 传统本体库（GraphDB）：多为静态离线推理，推理结果只读，没有仿真能力；
- OntoOS：支持创建独立沙盘副本，在副本中修改事实、触发推演，模拟连锁影响；支持因果传导推演，适合风险扩散、召回传导、应急影响研判。

### 5.4 存储引擎：多模融合本体数据库，不是RDF引擎外挂向量库
GraphDB、Virtuoso 是纯粹RDF推理库，向量、时序能力需要对接第三方组件；
OntoGraph 原生一体化：图谱本体 + 时序 + 空间 + 向量在同一个存储内核，支持带时间维度的本体演化、事实变迁追踪。

### 5.5 工程链路：一体化工作台，打通“建模-校验-查询-推演-执行”
Protégé+ROBOT 是分散工具链：编辑器、推理、CI脚本、业务系统互相独立，需要大量二次开发粘合；
OntoFlow是统一工作台，AI抽取、建模、校验、查询配置资产在同一个平台产出，资产直接供给上层推演引擎，链路打通。

### 5.6 执行安全模型：本体动作绑定审批流、审计链路
Agent框架、LangGraph、普通RAG工具：工具调用审批是上层应用代码实现；
Onto这套体系：**动作本身定义在本体模型内**，风险等级、审批规则和本体对象绑定，语义层面控制权限与审批，不是简单API网关拦截。

### 5.7 和GraphRAG的本质差异
GraphRAG：以大模型为主，图谱只是检索素材，答案依赖LLM生成，容易幻觉；
Onto体系：本体逻辑规则作为**主决策依据**，LLM是辅助抽取、辅助自然语言交互，结论由描述逻辑和规则保证确定性，适合强监管、高风险决策场景。

## 6. 适用场景边界 & 公开信息局限性
### 6.1 公开宣传典型落地场景
- 汽车供应链：零部件召回传导推演、库存韧性优化、备件调度仿真
- 公共安全、情报态势研判
- 能源资产运维、故障传导推演
- 金融风控、合规反欺诈
- 智能制造预测性维护
- 政务应急指挥、风险研判

### 6.2 局限（公开文稿没有覆盖、需要客观说明）
1. 整套产品为**商用闭源软件**，没有在GitHub放出完整开源版本；只有理念、方法论对外公开；
2. 公开材料偏向业务价值、理念，很少披露底层压测指标、大规模并发推理性能边界；
3. 属于决策推演型本体平台，不优先面向通用知识库问答、科普类知识图谱场景；
4. 虽然兼容OWL标准，但是Action/Function扩展层属于私有扩展定义，其他标准本体引擎无法直接识别这部分扩展语义。

## 7. 术语统一对照表（汇报统一口径，避免歧义）
| 术语 | 统一解释 |
| ---- | ---- |
| 活本体 / 可执行本体 | 带有Action、Function行为定义，支持推演、动作执行的本体模型，区别于静态OWL本体 |
| 对象优先建模 | 以业务对象、行为、规则为核心的建模方式，本体优先，数据表后置映射 |
| 沙盘推演 | 在隔离副本内仿真假设场景，不污染生产实例数据 |
| HITL 人在回路 | AI生成动作建议，高风险动作强制人工审批，可审计 |
| TBox | 本体概念、类、属性定义（模式层） |
| ABox | 本体实例、三元组事实（数据层） |
